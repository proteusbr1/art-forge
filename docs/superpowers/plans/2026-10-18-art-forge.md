# art-forge: implementation plan

> **For agentic workers:** use superpowers:subagent-driven-development (recommended) or
> superpowers:executing-plans, task by task. Steps use checkboxes (`- [ ]`). This plan
> holds no code by the maintainer's choice: each task gives files, contracts, behaviours
> to test and how to verify; code is written during execution. Source files from the
> author's earlier private projects are located through a local, unversioned source map
> (`local/private/sources.md`).

**Goal:** the factory ready to take orders from any game, including the new end-to-end
`humanoid` recipe, verified dry (no GPU inference).

**Architecture:** the factory core from the author's earlier factory, extended with
per-piece order keys, a per-stage option catalogue, an exclusive group for local GPU
stages, and local tools: a rig runner (SkinTokens by default, UniRig as option), a
humanoid exporter (Blender), a bone renamer to Godot's humanoid profile and a review sheet
rendered by Godot off-screen.

**Tech stack:** system Python 3 with NumPy and Pillow (factory); `bpy` 4.2 (exporter);
SkinTokens (rig; UniRig optional); Godot 4 standard edition with GDScript (sheet); Windows PowerShell 5.1
(launcher); local ComfyUI through its HTTP API only.

Design: `docs/superpowers/specs/2026-10-18-art-forge-design.md`.

## Global constraints

- No game names, briefs, prompts, images or outputs in the repository; examples and tests
  use generic subjects.
- Code, identifiers, script names and parameters in English; PowerShell compatible with
  5.1 and ASCII only.
- Local ComfyUI through its HTTP API only; workflows with paid API nodes refused on load.
- Media, weights, outputs and `forge.local.json` outside git.
- No GPU inference during this plan. Tests that need local tools (Blender, Godot,
  SkinTokens, UniRig)
  are skipped when the configuration does not point to them.
- Silent tests with no visible window: Godot with audio off and its window at
  (-20000, -20000).

## File structure

| Path | Responsibility |
|---|---|
| `AGENTS.md` | repository rules (constraints above, how to run, how to test) |
| `README.md` | what the factory is, recipes, how to write an order, how to run it |
| `docs/provenance.md` | origin and SHA-256 of every file seeded from earlier code |
| `docs/order.md` | order format: inherited and new keys, stage catalogue, examples |
| `docs/conventions.md` | output contract: `model.json`, bones, region mask, held-item sockets, motion library |
| `forge.local.example.json` | template of the machine configuration |
| `Run-Forge.ps1` | launcher (`-Order`, `-Out`, `-Check`, `-Estimate`, `-Status`, `-Stop`, `-Now`, `-Foreground`, `-RetryFailed`, `-Only`, `-Limit`) |
| `forge/` | the factory's Python package (core plus extensions) |
| `forge/workflows/` | production ComfyUI workflows in API format |

| `tests/` | unit and smoke tests; `tests/fixtures/` with synthetic orders, skeleton, item and motion library |

### Task 1: Core, extended order and launcher

**Files:** create `AGENTS.md`, `docs/provenance.md`, `docs/order.md`,
`forge.local.example.json`, `Run-Forge.ps1`, `forge/` (seeded core), `forge/config.py`,
`forge/order.py`, `forge/stages.py`, `forge/workflows/`, `tests/` (seeded and new tests),
`tests/fixtures/order_generic.json`; update `README.md`.

**Contracts:**
- `forge.order.load_order(path)` → the order dictionary with family defaults merged into
  each piece and `inputs` paths resolved to absolute (relative to the order file).
- `forge.order.check_order(order, config, server=None)` → list of problems (empty when
  valid). Checks: known recipe; `stages` options that exist for that recipe; valid `skip`
  names; `variants` a positive integer; `params` of the right types; `inputs` files
  present; tools required by the stages present in `config`; and, with a server, that
  ComfyUI has the node classes the workflows use (`/object_info`).
- `forge.config.load_config(path)` → `comfy_url`, `python`, `blender_python`,
  `skintokens_dir`, `skintokens_python`, `unirig_dir`, `unirig_venv`, `unirig_hf`,
  `unirig_shim`, `godot` (Task 2 adds the two `skintokens_*` keys if Task 1 did not).
- `forge.recipes.expand(order, only=None)` → job list, reading the merged keys.
- Kept from the core: manifest with specification hash, resume, frozen program copy in
  `<out>/program`, automatic picks marked for review, one retry, stop file, estimate,
  provenance export.

- [ ] **Step 1:** seed `forge/` with the earlier core modules, `tests/` with its art tests
  and `Run-Forge.ps1` from its launcher. Record source revision and SHA-256 of each seeded
  file in `docs/provenance.md` (describing the source as the author's earlier factory).
  Fix imports for the `forge` package. Run the seeded tests: they pass unchanged.
- [ ] **Step 2:** add only production workflows to `forge/workflows/`: Qwen Image 2.1 Turbo
  (t2i, hires, inpaint, tile), Qwen Image Edit 2511 (character and angles), Klein t2i,
  Hunyuan3D 2.1 shape and Paint. Add three derived workflows with `$NAME$` markers:
  `qwen_image_21_base_t2i.json` (standard nodes, 60 steps by default, no custom measuring
  sampler), `trellis2_mesh.json` (TRELLIS.2 with remesh, controllable `DecimateMesh`
  target and optional texture bake) and `hunyuan21_paint_mesh.json` (Paint over a given
  mesh, 10 steps, controllable texture size). No research-only workflows.
- [ ] **Step 3:** write the tests of `order.py`: family → piece merge; relative `inputs`
  paths; each problem `check_order` must report (unknown recipe, missing stage option,
  invalid `skip`, zero `variants`, missing input file, tool missing from the
  configuration, node class missing from a fake `/object_info`). Run: they fail.
- [ ] **Step 4:** implement `config.py`, `order.py` and the skeleton of `stages.py` (empty
  catalogue for the core recipes, which have no swappable stages). Run: they pass.
- [ ] **Step 5:** test of the specification hash: changing the content of an `inputs` file
  changes the hash only of the jobs that use it. Implement in the core (input hashes
  already cover outputs of other jobs; extend to external files).
- [ ] **Step 6:** launcher: `-Order` (required except with `-Status` and `-Stop`), `-Out`
  required and outside this repository (refuse a path inside it), `-Check` (runs
  `check_order` with the server if it answers, without it otherwise), reads
  `forge.local.json` from the repository root.
- [ ] **Step 7:** `tests/fixtures/order_generic.json` with one material, one 3D object and
  one concept family of generic subjects (stone, wooden crate, lantern). Verify `-Check`
  and `-Estimate` with it.
- [ ] **Step 8:** write `AGENTS.md`, `docs/order.md` and update `README.md` (complete
  format, inherited and new keys, model licence table with a link to each model's terms).
  Run every test. Commit.

**Verification:** all tests pass; `-Check` reports no problems and `-Estimate` gives job
counts and hours for the generic order; a search of the repository finds no game names.

### Task 2: Humanoid local tools (exporter, bones, sheet)

**Files:** create `tools/blender/humanoid_bones.py`, `tools/blender/humanoid_export.py`,
`tools/review_godot/` (project, scene and script), `forge/local_gpu.py` (the tool runners),
`docs/conventions.md`, `tests/fixtures/` (synthetic skeleton, item and library plus their
generator), `tests/test_humanoid_bones.py`, `tests/test_local_tools_smoke.py`.

**Contracts:**
- `humanoid_bones.py`: `bone_roles(armature)` → bone → role, found from the tree (root =
  hips; the chain going up = spine, the top's highest child = neck and head, the other two
  = arms; the root's other children = legs; left from where the toes point), and
  `godot_name(role)` → the `SkeletonProfileHumanoid` name (Hips, Spine, Chest,
  UpperChest, Neck, Head, LeftShoulder, LeftUpperArm, LeftLowerArm, LeftHand,
  LeftUpperLeg, LeftLowerLeg, LeftFoot, LeftToes and the Right equivalents). Bones without
  a role keep their original names. A pure part (no `bpy`, over a tree of points) is
  testable with the system Python.
- `humanoid_export.py` (runs in `blender_python`): `--rig <rigged glb>`, `--out <folder>`,
  `--name`, `--tris`, `--tex`, `--height` (metres), `--head`, `--hands`, `--feet`,
  `--widen` (default 1.0), `--clips <library json>` (optional), `--items <held items
  folder>` (optional), `--glow` with `--glow-hues` (optional). Writes `<name>.glb` with
  renamed bones, retargeted animations (rest pose only without `--clips`), a normal map
  baked from the full mesh, the painted texture at its original size; `model.json`;
  `regions_mask.png` (red skin, green hair, blue glow). A generic port of the earlier
  exporter without game-specific recolouring, level heights, per-tile phases or
  unit-specific options (those become motion-library fields or go away).
- `docs/conventions.md` documents `model.json` (keys in English), the motion library
  (canonical joints in body coordinates, what each pose holds, how the feet stand) and the
  held-item socket file.
- `tools/review_godot/`: command line with a list of GLBs (or failure marks), camera
  (`pitch` in degrees, list of `yaws`, figure height in pixels, orthographic), animation to
  show (default the first idle, else the rest pose) and PNG output. Each variant appears
  in every small direction plus one large front view, labelled by the script. Window off
  screen, audio off, exits by itself.
- `forge/local_gpu.py`: `run_rig(mesh, out, config, seed, method)` with `method`
  `skintokens` (default) or `unirig`, `run_export(rig, out, config,
  params, clips, items)`, `run_review(glbs, out, config, camera)`; each runs the external
  process, keeps `stdout`/`stderr` next to the output and returns the produced files or
  raises an error naming the log.

- [ ] **Step 1:** generator of synthetic fixtures: a simple capsule humanoid with unnamed
  bones in the rig tools' hierarchy (SkinTokens style: `bone_N` plus five-finger chains
  per hand), a "box" item with its socket file, and a library with an
  idle pose and an 8-frame step. The GLBs are generated by `blender_python` on the first
  test run, not committed.
- [ ] **Step 2:** tests of the pure part of `humanoid_bones.py`: correct roles on a
  standing tree, on a mirrored tree (left/right swapped) and on a tree with extra bones
  (which keep their names) and on a tree with finger chains under each hand (fingers keep
  their names; the hand is still found). Run: they fail. Implement. Run: they pass.
- [ ] **Step 3:** port the exporter as described, with the renamer. Smoke test (skipped
  without `blender_python`): export the synthetic humanoid with and without a library;
  re-import the GLB in a new process and check humanoid-profile bone names, animations
  present with the library's duration, height equal to `--height` within 1 cm, texture
  and normal map present, hands within 2 cm of the box's sockets in holding poses.
- [ ] **Step 4:** the Godot sheet project and `run_review`. Smoke test (skipped without
  `godot`): sheet of two variants and one failure; check image size, that every figure
  cell has non-transparent pixels and that the failure cell shows the failure mark.
- [ ] **Step 5:** `run_rig`: `skintokens` runs the configured SkinTokens checkout with its
  own Python (skeleton and weights transferred onto the given mesh, fixed seed, beam
  count as a parameter, no window); `unirig` runs UniRig's python steps (extract,
  skeleton, extract, skin, merge). No automatic test in this task (they use the GPU);
  `check_order` checks the paths of the chosen method.
- [ ] **Step 6:** smoke test with a real existing rig, no inference: run export and sheet on
  a rigged GLB given by the `FORGE_SMOKE_RIG` environment variable and a real motion
  library given by `FORGE_SMOKE_CLIPS` (never copied into the repository). Keep the sheet
  in `local/smoke/` and look at the image. Export the smoke provenance with
  `--provenance` and check it lists rig, library, tools and hashes. Write
  `docs/conventions.md`. Commit.

**Verification:** tests pass (smoke tests run on a machine whose configuration points to
Blender, Godot and UniRig); the real-rig sheet shows the character from above and from
the front, animated in its idle pose, with no visible window during the run.

### Task 3: The `humanoid` recipe in the queue, GPU exclusivity and sample order

**Files:** modify `forge/recipes.py`, `forge/stages.py`, `forge/factory_core.py`,
`forge/local_steps.py`, `forge/local_gpu.py`; create `tests/test_humanoid_recipe.py`,
`tests/test_local_gpu_schedule.py`, `tests/fixtures/order_humanoid.json`.

**Contracts:**
- `stages.py` defines for `humanoid` the stages `reference`, `pose`, `cutout`, `mesh`,
  `paint`, `rig`, `export`, `review`, with defaults and options: `reference` =
  `qwen21_base` (default), `qwen21_turbo`, `klein`, `input_image`; `pose` =
  `qwen_edit_2511` (default; corrects A-pose, open hands apart, full body, nothing held);
  `cutout` = `birefnet` (default), `qwen_edit_character`; `mesh` = `trellis2` (default),
  `hunyuan21`; `paint` = `hunyuan_paint` (default), `trellis2_texture`; `rig` =
  `skintokens` (default), `unirig`; `export` = `humanoid_export`; `review` =
  `godot_sheet`. Each option knows its workflow or tool, its
  group, whether it is heavy, its output roles and which `params` it reads. `skip`
  accepts `pose`, `paint` (TRELLIS.2's texture stays), `rig` and `export` (statue: the sheet shows
  the painted mesh).
- `recipe_humanoid(fam, a, st)` makes, for each seed of `seeds_for(family/piece,
  variants)`, the chain of jobs with ids `<family>/<piece>/v<seed>/<stage>`, then one
  piece `review` job (all variants) and one `final` job (the pick). Reference prompt:
  `brief`, tier, family style, `global` and the `view_humanoid` view (required in `style`
  when an order has a humanoid; it describes A-pose, empty hands away from the body, full
  body, grey background).
- New job kinds: `local_gpu` (group `local_gpu`; runs `run_rig`, `run_export` or, for the
  sheet, `run_review`, since Godot also uses the card) and `final` (local; copies the
  chosen variant to `final/`; the pick uses the core's manual pick mechanism; the
  automatic pick takes the first variant that finished every stage and marks it for
  review).
- Scheduler exclusivity: a `local_gpu` job starts only with no factory prompt in the
  server queue and after `/free`; while it runs nothing is sent to ComfyUI. The estimate
  gains times for `trellis2`, `hunyuan_paint`, `qwen21_base` and `local_gpu` (initial
  values from earlier measurements, marked as estimates).
- Folder inputs (for example `inputs.items`) enter the specification hash by the hashes
  of the files inside them (sorted relative paths and contents), so changing one held
  item redoes only the jobs that use the folder.
- A failed variant does not block the others; `review` runs with the variants that
  finished and marks the failures; `final` waits for at least one complete variant.

- [ ] **Step 1:** expansion tests: job count per `variants`; stable ids; a `stages` option
  change swaps the workflow of the right job and changes only its hash and its
  dependants'; `skip` of `paint` turns on TRELLIS.2's texture bake; `params.tris` and
  `params.texture` reach the workflows; `inputs.clips` and `inputs.items` reach `export`;
  `review` receives every variant; a piece without `view_humanoid` in the style is
  reported by `check_order`. Run: they fail. Implement `stages.py` and
  `recipe_humanoid`. Run: they pass.
- [ ] **Step 2:** scheduler tests with a fake server (the core's tests already have one):
  `local_gpu` waits for the queue to drain and asks for `/free`; nothing is sent during a
  `local_gpu` job; a heavy Hunyuan job and a `local_gpu` job never overlap; a failed
  variant lets the others go on and `review` comes out with the failure mark. Run: they
  fail. Implement in `factory_core.py` and `local_steps.py`. Run: they pass.
- [ ] **Step 3:** `tests/fixtures/order_humanoid.json`, generic: a `crew` family with two
  humanoids (a technician in overalls and a guard in a vest), 4 variants, a review camera
  from above at 60 degrees with 8 directions, library and items pointing to the synthetic
  fixtures. `-Check` reports no problems (with the server up, checking node classes
  without sending anything) and `-Estimate` gives counts and hours.
- [ ] **Step 4:** update `README.md` and `docs/order.md` with the recipe, the stage
  catalogue and the example. Run every test. Commit.

**Verification:** all tests pass; `-Check` on the humanoid order confirms the ComfyUI
node classes of the machine without sending a prompt; `-Estimate` shows jobs and hours
per group.
